# Validation and security

Use Node.js **22.18.0 or newer**, npm, Git, Gitleaks 8 and a running Docker daemon. Browser tests require the Chrome channel used by the Playwright configurations. Install the declared dependencies with `npm ci` before local checks. The gate creates its own dependency installation from the snapshot's `package-lock.json` with lifecycle scripts disabled.

## Commands

```sh
npm run check:i18n
npm run check:security
npm run test:tooling
npm run check:working-copy
```

`check:working-copy` validates an isolated source copy, including untracked source files, and works before the first Git commit or before repository initialization. Generated directories, dependencies, CodeGraph databases and local agent artifacts are excluded. It never reuses the working directory's `node_modules`, `.next` output or Storybook server.

After initializing the repository, install the real hook:

```sh
git config core.hooksPath .githooks
```

Stage the complete project and run `npm run check:staged` to test the hook without committing. `npm run check:security:staged` checks only security against the same full index snapshot. No command creates commits, stages files, stashes changes or changes the working copy. Standard Git hooks can be bypassed by an explicit Git option; require the same checks in CI for protected branches.

## Complete staged snapshot

The hook exports every stage-0 index blob by object ID into a temporary directory, preserving executable modes. It does not use Git archives, so `export-ignore`, `export-subst`, checkout filters and unstaged fixes cannot change the checked content. Unmerged entries, symlinks, submodules and force-staged generated/dependency files fail validation. An index change during validation also blocks completion.

In that snapshot the hook runs security scanners, installs the locked dependencies, validates locale parity, runs TypeScript, ESLint, FSD, structure, React quality, formatting, Knip, Vitest unit/integration/tooling tests, the production build, the Storybook build, Storybook browser tests and Playwright E2E.

Storybook tests and Playwright projects cover mobile, tablet and desktop. E2E serves the snapshot's built Storybook on a newly allocated loopback port with `reuseExistingServer: false`. The working-copy server cannot satisfy snapshot tests. Temporary files, dependencies and reports are removed on normal completion and on validation failure.

## Scanners

Gitleaks scans the entire source snapshot, including tests, configuration and the generated MSW worker, with upstream detectors and an additional Telegram token detector. In-file allow comments and repository ignore fingerprints cannot suppress findings. Reports are temporary, credentials are fully redacted and scanner output is never printed.

Semgrep uses the official `semgrep/semgrep:1.181.0` image pinned to:

```text
sha256:81474464c1f07483ba0682a44787fd93c91397419762a04abe2bafaae396304b
```

A missing image is pulled by digest. The scan container has no network, a read-only source mount, a read-only root filesystem, dropped capabilities and a temporary writable report mount. Missing tools, Docker failures, invalid reports, parse errors, scanner errors and skipped eligible sources block validation. Every JavaScript/TypeScript source must appear in Semgrep's scanned path list. `.mts`/`.cts` files fail closed until their parser handling is explicitly implemented. Repository `.semgrepignore` files are rejected and inline suppressions are disabled.

The only JavaScript SAST exclusion is `public/mockServiceWorker.js`, generated by the installed MSW package. Its request-forwarding implementation is upstream runtime code; Gitleaks still scans it. Dependencies and generated build outputs are excluded from both scanners and cannot be force-staged through the hook.

`.semgrep/*.yml` vendors the applicable Node.js eval/VM, command execution and Node/Playwright SSRF High/Critical rules from the reference project's SecObserve subset. Electron, PostgreSQL and Express-only rules were omitted because this application does not use those technologies. The Node SSRF sink alternatives were split into three equivalent rules to keep each file under 200 lines; messages were shortened without changing matching patterns. The source ruleset was generated with Semgrep 1.181.0 and `sast-rules` revision `53bf5cf6df3c`. Rule metadata retains its upstream provenance and licenses (GitLab MIT; LGPL-3.0 for `rules_lgpl_*` ports).

All rule files and `.gitleaks.toml` have SHA-256 pins in `scripts/security/rules.mjs`. A deliberate rules update must update those pins and be reviewed. There is no inherited finding assessment, baseline or allowlist.

## Locale validation

`src/shared/lib/i18n/dictionaries/ru.ts` is canonical. Each additional `*.ts` locale file exports an object with the same name as its filename (for example, `en.ts` exports `en`). The checker parses TypeScript object literals without executing locale code. Recursive leaf keys and interpolation placeholder names/counts must match; empty strings, empty objects, dynamic values, spreads and duplicate keys fail. Locale key typing remains enforced by the application's i18next TypeScript declarations.
